# Bubble 0.7.1 — notification hiding and optional edge access

Long-press the fullscreen floating/minimize control or a floating chooser/chat's minimize control to park directly in the existing persistent notification. No intermediate bubble appears. Ordinary tapping is unchanged. Notification denial refuses hiding without dismissing the workspace. Fixed the old service HIDE branch incorrectly acknowledging success when parking failed.

Browser menu > Bubble / edge access, or the floating chooser > Edge access, configures an opt-in alternative to the bubble. One short side strip (12–28dp wide, 64–160dp tall) handles an inward swipe to the chooser and a hold to the selected chat. Side, vertical position and dimensions are adjustable; the faint grey indicator can be disabled. Real keyboard focus stays with the app below until a chat is opened. Vertical/outward/short/cancelled/multi-touch gestures do not open a chat. Only the tiny strip consumes input; no full-screen listener, accessibility service, input replay, top/bottom system-bar interception or privileged API is used. Android Back is excluded only within that strip using public gesture-exclusion rectangles. Edge conflicts in that small area remain a real tradeoff, not a claim of zero interception.

Normal minimize/Home/Back uses the chosen access mode. Explicit hide-to-notification removes BOTH bubble and edge. Restore uses the saved access mode; Use bubble instead is a direct notification Activity PendingIntent that also turns off edge mode for recovery. Notification taps and edge gestures retain the exact GeckoSession. The edge is not a second browser renderer. Edge settings are a separate small app-private AtomicFile with ordered off-main-thread reads/writes; old workspace data is not migrated or deleted. A preference load does not auto-show hidden UI. Failed edge attachment falls back to the bubble or a recoverable notification. The indicator has no idle animation loop. Panel exit moves slightly toward the chosen side without scaling webpage text; entry is anchored at that side. Grey black-glass theme and permanent signing identity remain.

No boot start, keyguard/secure-screen bypass, force-stop restart, OS-sleep override or invisible full-screen overlay is introduced. No claim of real-device 120fps is made. AccessPreferences errors preserve the old file and retain a usable in-session mode. Android can disable overlays in secure screens; the notification remains the recovery route.

Build submission: new pure policy tests and an actual Android long-press / SystemUI notification / edge-swipe test are added to the full suite. Record observed CI evidence separately. Earlier black-glass build 5cca320 passed 15 Android tests; this does not establish results for 0.7.1.

Carry-forward: all-web foreground compatibility, native long-press Back/quick-tabs tools, local prompts/pins/notes and prior notifications remain. No download implementation was added in this change; browser downloads and live-provider attachment verification from the earlier request remain outstanding.
