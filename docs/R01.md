# r01 — floating-head core

## Acceptance criteria

1. User can browse normal HTTP(S) sites in an Android WebView.
2. User can create multiple logical tabs without an artificial count limit.
3. Any active tab can be minimized into its own overlay head after granting Android overlay permission.
4. Every head can be dragged independently.
5. Releasing a dragged head persists its X/Y position.
6. Tapping a head restores the corresponding logical tab and removes that overlay.
7. A received favicon is used for that tab's head; otherwise a deterministic site/title initial is shown.
8. Minimized tab metadata survives Activity recreation and process/service restart; a URL fallback remains available when process-local WebView state is gone.
9. Inactive tabs do not require one permanently live WebView each.
10. CI builds a debug APK on pushes and pull requests.

## Explicitly deferred

- head stacking/fan-out gestures
- edge magnetism and spring physics
- drag-to-trash target
- expanded floating browser cards
- disk-level WebView/session hibernation
- private/incognito tab containers
- ad/tracker blocking
- Chromium engine replacement or GeckoView integration
- sync/bookmarks/password manager
- polished visual design and animation pass

Those are separate version-controlled milestones rather than hidden scope inside r01.
