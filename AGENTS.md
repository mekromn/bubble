# Bubble implementation contract

The user requested a clean browser rewrite on September 4, then interactive floating chat, tab selection from the bubble, native PiP, Home/Back minimization and compact animated UI on September 5, 2026. `docs/FLOATING_V060.md` supersedes older requirements that limited heads to launching a fullscreen Activity.

Keep the existing debug signing identity, package and compatible workspace file. Never rotate the key as part of a fix. No production signing secrets. No browser bootstrap in Application.onCreate or Gecko subprocesses. All Gecko operations are main-thread; disk IO is off-main-thread. There is one process-owned runtime and durable UUID tabs. A GeckoSession has exactly one display owner: fullscreen Activity or interactive floating WindowContext. Only the floating view uses TextureView for animated clipping; fullscreen retains SurfaceView. No fullscreen transparent touch-routing shim.

Use one compliant foreground service for one visible bubble/chooser/chat overlay. Minimize only as an explicit user command or user Home/Back action; do not let saved data dismiss an Activity. User file/permission flows must not trigger Home minimization. Native Android PiP is separately labeled view-only. No arbitrary logical tab cap, no voluntary suspension of open workspace sessions. Real input focus belongs only to the selected visible view. The ChatGPT foreground compatibility script is exact-origin, top-frame and exposes no native API.

Never bypass TLS, grant arbitrary site permissions or add network analytics. Do not call compilation a runtime proof. Do not claim physical 120fps or zero jank based on a refresh request, a screenshot or a software-rendered emulator. Verify actual compositor pixels, input, floating/fullscreen handoffs and session identity in tests; record remaining device gates honestly.
